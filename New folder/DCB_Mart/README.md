# DCB_Mart — query-ready tables for the chatbot (built, not locked)

`build_mart.py` reads the **locked** star schema (`../DCB_Star_Schema/dcb_star_schema.sqlite`, opened `mode=ro`,
its SHA-256 checked unchanged after the build) and writes, in this folder only:

| File | What |
|---|---|
| `dcb_mart.sqlite` | `mart_*` tables (below), `semantic_*` docs / registry / capabilities / issues, `ledger_*` build checks |
| `mart_semantic_layer.json` | the same docs + entity lists, exported for the app (the app only reads it) |
| `../dcb-ai-app/integrity_manifest.json` | SHA-256 of every file the app only reads (`tests/test_pipeline_api.py::test_inputs_unchanged`) |

This folder is **not** one of the 4 locked folders: it is regenerated by the script. The metadata below is hand-written
and is the single source of truth.

```
python DCB_Mart/build_mart.py        # ~0.5 s; stop the app server first (Windows can't replace an open file)
```

## Tables (the app's deterministic routes read only these; model SQL may read these and the reviewed star tables)

| Table | Grain |
|---|---|
| `mart_dim_fiscal_year`, `mart_dim_subdivision`, `mart_dim_tariff`, `mart_dim_tariff_family` | dimensions |
| `mart_fact_division_year` | fiscal year, whole division — the printed GRAND TOTAL, plus printed LT / HT / misc totals |
| `mart_fact_subdivision_year` | fiscal year × sub-division / section (geographic units only) |
| `mart_fact_family_division_year` / `_subdivision_year` | fiscal year × tariff family (LT-1 … HT-7, MISC) — summed from line items |
| `mart_fact_slab_division_year` / `_subdivision_year` | fiscal year × tariff slab, as printed |

Every fact carries the same metric columns (demand, collection, balances, installations incl. a single comparable
`dc_mnr_installations`, load, consumption, `uncollected_demand`) and per-row ratios (`collection_efficiency_pct`, …).

## Metadata (`metadata/`)

| File | Used for |
|---|---|
| `semantic_docs.json` | grain + doc of every mart table and column (the build fails on an undocumented column), rules |
| `metric_registry.json` | 20 KPIs: synonyms, unit, kind (flow / stock / ratio), SUM/SUM expressions; non-averageable columns |
| `capability_manifest.json` | what the data can't answer (monthly, consumers, other divisions, rates, losses, …) with the note shown |
| `known_issues.json` | KI-01 … KI-12, the one-line caveat attached to affected answers |

## Build checks (all must PASS or nothing is written)

Families add up to the printed grand total (division and every sub-division, all 28 metrics); sub-divisions agree with
the division on installations and LT/HT demand; golden figures (Arkalgud 2024-25 93.62 %, Konanur 2025-26 97.46 %,
HT-2 2015-16 ₹23,399,034.75, LT-1 2025-26 = the sheet's "Total of LT-1", LT-5 2015-16 = "Sub Total of LT-5 (a+b)",
division 2024-25 = printed grand total); every family total equals the printed family subtotal wherever the sheet prints
one (847 matches; the one exception is KI-01); no Division_Total / Division_Office in sub-division facts; DC/MNR present
every year; no negative installations; every column documented; every "loaded" capability has rows.

## Facts about the data this build surfaced (see `metadata/known_issues.json`)

All three below were re-verified straight from the raw workbook by `verify_against_raw.py` (run it after a rebuild:
`python DCB_Mart/verify_against_raw.py`, ~11 s, writes `../reports/raw_reverification.md`). `metadata/knowledge_base.yaml`
is the hand-written general-knowledge base (EN / KN) the chatbot answers general questions from.

- **KI-05** the printed "Sub Total of LT-5" is **0** up to 2023-24 (the real family total is in "Sub Total of LT-5 (a+b)");
  anything reading the printed family subtotal got LT-5 = 0 — the chat prompt's family rule and the Reports page did.
- **KI-02** from 2019-20 the division's own block books miscellaneous revenue (mainly 62.9177) no sub-division carries:
  the division total is up to 3.475 % (2024-25) above the sum of its sub-divisions. LT, HT and installations agree exactly.
- **KI-01** from 2024-25 the sheet prints the BMA / urban-local-body lighting slabs (LT-2(a) before) under LT-1; the
  2025-26 sheet's own "Total of LT-1" includes them, and so does the mart's LT-1 (slab rows carry `source_note='LT-1 A'`).
- **KI-11** Holenarasipura's 2023-24 grand total leaves total consumption blank (taken as metered + assessed).
- **KI-12** 2015-16 division installations are 98 above the sum of its sub-divisions (every later year agrees).
